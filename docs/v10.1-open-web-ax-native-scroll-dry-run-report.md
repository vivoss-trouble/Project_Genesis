# Genesis v10.1 AX Native Scroll Dry-Run Report

## Result

The v10.1 dry-run passed and did not mutate browser state.

Key receipt fields:

```json
{
  "web_area_found": true,
  "scroll_area_found": true,
  "vertical_scrollbar_found": false,
  "web_area_actions": ["AXScrollToVisible", "AXShowMenu"],
  "scroll_area_actions": ["AXScrollToVisible", "AXShowMenu"],
  "selected_primitive": "none",
  "ax_mutation_attempted": false,
  "visual_change_detected": false,
  "url_changed_after_ax": false,
  "window_id_stable": true
}
```

## Interpretation

Safari exposes the Rust Book page as an `AXWebArea`, and that web area has a
nearest `AXScrollArea`, but the native controls visible from this layer do not
include a page-scroll action. The only exposed actions on the web content path
are:

- `AXScrollToVisible`
- `AXShowMenu`

The probe also found no writable vertical scrollbar for the page content.

This means v10.1 should not be connected to Hunter as a scroll actuator. It is
still valuable because it proves the failure mode is clean: the AX control plane
can locate the content container, but does not expose a direct native page-scroll
primitive at this tree depth.

## Next Probe

The next safe direction is to inspect parameterized AX attributes and deeper
scroll descendants without executing actions:

- `AXUIElementCopyParameterizedAttributeNames`
- `AXUIElementCopyAttributeNames`
- bounded traversal below `AXWebArea` for scroll-related descendants only
- explicit filtering for page content vs Safari chrome/bookmarks scroll areas
