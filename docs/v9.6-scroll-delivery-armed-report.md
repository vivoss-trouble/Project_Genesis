# v9.6 Armed Scroll Delivery Probe Report

## Scope

This report records the first armed v9.6 scroll-delivery probe against the Rust
Book page in Safari.

The probe was intentionally limited to scroll events. It did not click, and it
did not expect URL navigation. The goal was to measure whether Safari converts
CoreGraphics scroll events into visible page displacement after the driver pins
the event location with `CGEventSetLocation`.

## Variants

| Variant | Requested Unit | Requested dy | Posted | Mean Target Y Delta | Visual Change |
| --- | --- | ---: | --- | ---: | --- |
| 0 | pixel | 66 | true | 0.0 | false |
| 1 | line | 3 | true | 0.0 | false |
| 2 | pixel | 240 | true | 0.0 | false |
| 3 | line | 6 | true | 0.0 | false |

All four variants reported:

- `scroll_status=ok`
- `scroll_posted=true`
- `target_intersection_ratio=1.0`
- `target_signature_changed=false`
- `url_changed=false`

## Physical Conclusion

The OS delivery layer is posting the scroll events successfully, and the cursor
is pinned to the requested scroll point. However, Safari did not convert any of
the tested CoreGraphics scroll-wheel events into observable page movement.

The measured absorption ratio is therefore:

```text
observed_window_y_delta / requested_dy = 0.0
```

for both pixel-unit and line-unit variants in this run.

## Architecture Implication

The v9.5 autonomous-hunt failure was not caused by target selection, occlusion
checking, or the hunter's Remap court. The current bottleneck is scroll delivery
semantics: `CGEventCreateScrollWheelEvent` events can be posted successfully yet
still produce no visible Safari page displacement.

The next safe cut should stay below fire control and test a different physical
scroll primitive before rearming v9.5:

- keyboard scroll primitives such as Space, PageDown, or ArrowDown;
- a Safari-focused event route that first makes the web content area first
  responder;
- or a platform-specific accessibility scroll action if it can remain isolated
  from Genesis Core.
