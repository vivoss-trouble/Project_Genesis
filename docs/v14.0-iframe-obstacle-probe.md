# Genesis v14.0 Iframe Obstacle Probe

v14.0 isolates iframe boundaries before trying them on the open web.

## Branches

### v14.0a Same-Origin Iframe

The host page covers `Next chapter` with a same-origin iframe. The iframe
contains the standard four-control obstacle fixture:

- `Close`: legal
- `Accept all`: trap
- `Subscribe`: trap
- `Continue`: trap

Expected result:

```json
{
  "candidate_count": 4,
  "legal_candidate_count": 1,
  "rejected_candidate_count": 3
}
```

Armed mode may click the single legal `Close` candidate and requires
`target_clear_after=true`.

### v14.0b Sandbox Iframe

The host page covers `Next chapter` with a sandbox iframe that exposes no
whitelisted clearance control. The correct result is safe death:

```json
{
  "occluder_kind": "iframe",
  "candidate_count": 0,
  "legal_candidate_count": 0,
  "stop_reason": "iframe_occluder_unresolved"
}
```

The sandbox branch is always read-only in the v14.0 runner.

## Commands

Dry-run:

```bash
./scripts/validate_v140_iframe_obstacle_probe.sh
```

Armed same-origin branch:

```bash
GENESIS_V140_ARMED_CONFIRM=GENESIS_V140_ARMED_IFRAME_OBSTACLE \
GENESIS_V140_AUTO_FIRE_CONFIRM=GENESIS_V140_AUTO_FIRE_IFRAME_OBSTACLE \
./scripts/run_v140_iframe_obstacle_probe.sh
```

## Probe Changes

`ax_obstacle_clearance_probe.swift` now distinguishes:

- `modal`: real dialog-like obstacle, selected before iframe-like containers.
- `iframe`: iframe-like coverage that exposes no legal clearance control.
- `none`: no recognized obstacle.

The probe does not treat a page title containing the word `iframe` as armor.
Iframe armor requires a specific iframe obstacle label such as
`iframe obstacle` or `iframe visual obstacle`.
