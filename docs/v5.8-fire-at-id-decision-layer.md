# Genesis v5.8 Fire-at-ID Decision Layer

v5.8 introduces the first tactical selection layer above the v5.7 visual
topology. It consumes `marker_candidates` and the controlled Native Dummy target
metadata, then selects exactly one target by explicit id.

## Boundary

- `genesis-core` is unchanged.
- `genesis-os-driver` is unchanged.
- The decision layer is a script-level tactical gate, not a microkernel feature.
- No heuristic policy is introduced yet.
- No retry, backoff, semantic ranking, or model-driven choice is introduced.

## Flow

```text
Window pixels
  -> marker_candidates[]
  -> map candidates to target ids by nearest marker center
  -> explicit target_id policy
  -> selected CoreGraphics point
  -> os-driver dry-run or armed single shot
```

## Command

Dry-run selection of the center target:

```bash
GENESIS_V58_TARGET_ID=native-heal-b \
  ./scripts/run_v58_fire_at_id.sh
```

Controlled armed shot:

```bash
GENESIS_V58_TARGET_ID=native-heal-b \
GENESIS_V58_ARMED_CONFIRM=GENESIS_V58_ARMED_FIRE_AT_ID \
GENESIS_V58_AUTO_FIRE_CONFIRM=GENESIS_V58_AUTO_FIRE_NATIVE_DUMMY \
  ./scripts/run_v58_fire_at_id.sh
```

## Evidence Shape

The gate emits a structured target set:

```json
{
  "event": "vision_target_set",
  "target_set": [
    {
      "target_id": "native-heal-b",
      "candidate_id": "marker-1",
      "candidate_distance_px": 0.0,
      "global_coregraphics_point": {"x": 370.0, "y": 827.0}
    }
  ]
}
```

Then it emits the selection:

```json
{
  "event": "selection_policy",
  "policy": "explicit_target_id",
  "requested_target_id": "native-heal-b",
  "selected": {
    "target_id": "native-heal-b",
    "candidate_id": "marker-1"
  }
}
```

## Validation

```bash
./scripts/validate_v58_fire_at_id.sh
```

The validation is dry-run only and asserts:

- window-scoped capture
- all three Native Dummy targets are mapped
- no unmapped marker candidates remain
- `native-heal-b` selects `marker-1`
- OS-driver receipts stay `posted=false`

## Next Boundary

v5.9 adds pure spatial policy selectors such as `leftmost`, `rightmost`, and
`nearest_to_window_center`. Those policies consume `vision_target_set`, not raw
pixels.
