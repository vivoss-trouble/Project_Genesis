# Genesis v10.0 Open-Web AX WebArea Key Armed Report

## Command

```bash
GENESIS_V100_ARMED_CONFIRM=GENESIS_V100_ARMED_OPEN_WEB_AX_WEBAREA_KEY \
GENESIS_V100_AUTO_KEY_CONFIRM=GENESIS_V100_AUTO_KEY_WEBAREA_PROBE \
./scripts/run_v100_open_web_ax_webarea_key_probe.sh
```

## Target

- URL: `https://doc.rust-lang.org/book/`
- Browser: Safari
- Restricted key: `page_down`

## Key Receipt

The restricted key posted, did not change URL, and did not move content:

```json
{
  "requested_key": "page_down",
  "key_posted": true,
  "url_changed_after_key": false,
  "key_visual_change_detected": false,
  "key_absorbed_by_content": false

```

## Interpretation

v10.0 proves that Genesis can locate and focus Safari's `AXWebArea` without
physical input and without URL drift. It also proves that focusing the web area
is still insufficient for synthesized `page_down` to produce WebKit content
scrolling.

The v9.7 failure mode is gone: the key no longer escapes to an unrelated URL.
The remaining failure mode is deeper: WebKit does not convert this posted
keyboard primitive into page displacement, even when AX reports the focused role
as `AXWebArea`.

The hunter controller must still not consume keyboard scrolling.

## Next Cut

The next viable primitive should not assume keyboard scrolling. Candidate
directions:

- AX native scroll action on `AXWebArea` or its nearest `AXScrollArea`;
- AX value/parameterized scroll attributes if exposed by Safari;
- a browser-specific JavaScript-free accessibility action that moves the web
  area without DOM automation;
- return to visual click/URL navigation while leaving scroll acquisition out of
  autonomous hunting.
