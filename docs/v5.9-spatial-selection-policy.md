# Genesis v5.9 Spatial Selection Policy

v5.9 adds deterministic spatial policies above the v5.8 Fire-at-ID target set.
It still does not touch `genesis-core`, `genesis-os-driver`, or pixel detection.

## Boundary

- Input is `vision_target_set`, not raw pixels.
- Output is one selected target and one CoreGraphics point.
- Policies are pure functions over the mapped target set.
- No model, retry, semantic priority, or temporal smoothing is introduced.

## Policies

Set `GENESIS_V58_SELECTION_POLICY` before running the tactical gate:

```text
explicit_target_id
leftmost
rightmost
nearest_to_window_center
```

`explicit_target_id` remains the default and uses `GENESIS_V58_TARGET_ID`.

## Examples

```bash
GENESIS_V58_SELECTION_POLICY=leftmost \
  ./scripts/run_v58_fire_at_id.sh
```

```bash
GENESIS_V58_SELECTION_POLICY=nearest_to_window_center \
  ./scripts/run_v58_fire_at_id.sh
```

Controlled armed shot is still gated:

```bash
GENESIS_V58_SELECTION_POLICY=rightmost \
GENESIS_V58_ARMED_CONFIRM=GENESIS_V58_ARMED_FIRE_AT_ID \
GENESIS_V58_AUTO_FIRE_CONFIRM=GENESIS_V58_AUTO_FIRE_NATIVE_DUMMY \
  ./scripts/run_v58_fire_at_id.sh
```

## Expected Native Dummy Policy Results

```text
leftmost                 -> native-heal-a -> marker-0
rightmost                -> native-heal-c -> marker-2
nearest_to_window_center -> native-heal-b -> marker-1
```

## Validation

```bash
./scripts/validate_v59_spatial_selection_policy.sh
```

The validation runs all three spatial policies in dry-run mode and asserts that
OS-driver receipts remain `posted=false`.
