# Genesis v6.3 Calculator Sequence Fire Control

v6.3 extends the Calculator single-shot gate into a deterministic sequence loop.
It still defaults to dry-run.

## Boundary

- Each step remaps Calculator before firing.
- Each step posts at most one `move_mouse` and one `click_point`.
- A fixed settle interval follows each step.
- No frame differencing.
- No OCR.
- No semantic expression verifier.

## Default Sequence

```text
calculator-cell-r3-c0,calculator-cell-r3-c3,calculator-cell-r3-c1
```

This is a topology sequence, not a semantic calculator expression contract.
Override it with:

```bash
GENESIS_V63_TARGET_SEQUENCE=calculator-cell-r4-c2,calculator-cell-r3-c3
```

## Fixed Settle

```bash
GENESIS_V63_SETTLE_MS=500
```

The fixed wait intentionally separates sequence control from visual stability
research. Adaptive frame differencing is left to a later version.

## Dry-Run Validation

```bash
./scripts/validate_v63_calculator_sequence.sh
```

The validation asserts:

- one fresh map per sequence item
- action ids bind target ids and step indexes
- OS-driver receipts remain `posted=false`
- the sequence summary reports the expected step count and settle interval

## Armed Sequence

The armed path requires both keys:

```bash
GENESIS_V63_ARMED_CONFIRM=GENESIS_V63_ARMED_CALCULATOR \
GENESIS_V63_AUTO_FIRE_CONFIRM=GENESIS_V63_AUTO_FIRE_SEQUENCE \
GENESIS_V63_TARGET_SEQUENCE=calculator-cell-r3-c0,calculator-cell-r3-c3,calculator-cell-r3-c1 \
  ./scripts/run_v63_calculator_sequence.sh
```

## Invariant

Map, fire, settle. Never reuse a prior Calculator coordinate for the next shot.
