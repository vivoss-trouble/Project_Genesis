# Genesis v10.1 Open-Web AX Native Scroll Probe

v10.0 proved that Safari can expose and focus an `AXWebArea`, but WebKit still
does not absorb synthesized `page_down` keyboard input. v10.1 stops pretending
to be hardware and probes the native Accessibility control surface directly.

## Boundary

The probe does not use `genesis-os-driver`.

Default mode is read-only:

- open the target page,
- capture a pre-AX Shadow Map,
- traverse the Safari AX tree,
- find the first bounded `AXWebArea`,
- enumerate `AXActionNames` on the web area and nearest `AXScrollArea`,
- inspect the first vertical `AXScrollBar` value and writability,
- capture a post-AX Shadow Map,
- assert URL/window/topology stability.

No AX mutation is attempted unless the armed double key is present.

## AX Primitives

`scripts/ax_native_scroll_probe.swift` can test two native control-plane
families:

- `action`: perform an exposed AX action such as `AXScrollDown` on `AXWebArea`
  or its nearest `AXScrollArea`;
- `scrollbar_value`: write a bounded delta to the first vertical
  `AXScrollBar` if `AXValue` is settable.

`GENESIS_V101_AX_PRIMITIVE=auto` prefers an available action, then falls back
to a writable vertical scrollbar.

## Armed Probe

Armed mode requires both keys:

```bash
GENESIS_V101_ARMED_CONFIRM=GENESIS_V101_ARMED_OPEN_WEB_AX_NATIVE_SCROLL \
GENESIS_V101_AUTO_AX_CONFIRM=GENESIS_V101_AUTO_AX_NATIVE_SCROLL_PROBE \
./scripts/run_v101_open_web_ax_native_scroll_probe.sh
```

The armed probe is accepted only if:

- `url_changed_after_ax=false`,
- `window_id_stable=true`,
- `ax_mutation_attempted=true`,
- `ax_content_moved=true`.

If AX control changes the URL, the script emits
`v101_ax_native_scroll_abort` and fails fast.

## Validation

```bash
./scripts/validate_v101_open_web_ax_native_scroll_probe.sh
```

Validation remains dry-run and requires:

- `web_area_found=true`,
- `ax_mutation_attempted=false`,
- `posted=false`,
- `os_driver_active=false`,
- `visual_change_detected=false`,
- `url_changed_after_ax=false`.
