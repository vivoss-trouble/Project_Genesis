## Parameterized Surface

The web area and nearest scroll ancestor expose a large text-marker control
surface, including:

- `AXBoundsForTextMarkerRange`
- `AXStartTextMarkerForBounds`
- `AXTextMarkerForPosition`
- `AXTextMarkerRangeForUIElement`
- `AXUIElementForTextMarker`
- `AXSearchTextWithCriteria`
- `AXSelectTextWithCriteria`
- `AXTextOperation`

These are read/query primitives around text geometry and selection. The probe
did not find a direct page-scroll parameterized attribute.

## Control Surface

The aggregate action set was limited to:

- `AXPress`
- `AXScrollToVisible`
- `AXShowMenu`

This confirms v10.1's boundary: the WebKit AX tree exposes rich geometry and
text-marker introspection, but not a direct global page-scroll actuator at this
bounded depth.

## Next Cut

The likely next primitive is not global scroll. It is target-centric movement:
use `AXUIElementForTextMarker` / `AXTextMarkerForPosition` / `AXScrollToVisible`
to test whether a specific descendant can be brought into view safely, then let
Shadow Map verify the visual remap.
