# Genesis v6.6 Calculator Display Assertion

v6.6 adds a read-only assertion layer for Calculator results. It does not use
OCR and it never posts physical actions.

## Goal

Prove that Genesis can verify a visible Calculator state by comparing the
display-area pixel slice against a sealed baseline.

## Components

- `scripts/calculator_display_hash.swift`
  - captures the Calculator window with `CGWindowListCreateImage`
  - derives `calculator-display-screen` from the button grid
  - writes a display crop PNG and debug overlay
  - emits exact FNV-1a hash, 8x8 average hash, mean RGB, bbox, and optional
    comparison evidence
- `scripts/capture_v66_calculator_display_baseline.sh`
  - captures the current display state as a baseline JSON and PNG
- `scripts/assert_v66_calculator_display.sh`
  - compares the current display state against a baseline
- `scripts/validate_v66_calculator_display_assertion.sh`
  - validates positive and negative assertions in dry-run

## Assertion Event

```json
{
  "event": "calculator_display_hash",
  "target_id": "calculator-display-screen",
  "match": true,
  "changed_pixel_ratio": 0,
  "hash_distance": 0,
  "posted": false
}
```

The positive path compares the current display to a freshly captured baseline.
The negative path mutates the baseline average hash and must return
`match=false`. A verifier that cannot say no is not a verifier.

## Validation

```bash
./scripts/validate_v66_calculator_display_assertion.sh
```

This redline is fully read-only. It does not arm `genesis-os-driver`, does not
move the cursor, and does not click Calculator.

## Invariant

Map, fire, settle, assert is the future closed loop. v6.6 implements only the
assertion science. It does not connect assertion back into armed sequencing.
