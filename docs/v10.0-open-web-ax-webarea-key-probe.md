# Genesis v10.0 Open-Web AX WebArea Key Probe

v9.9 proved that focusing the outer Safari window prevents URL escape, but does
not make `page_down` reach the page content. v10.0 descends one layer deeper
into the Accessibility tree and tries to focus the first bounded `AXWebArea`
before sending a single restricted key.

## AX Boundary

`scripts/ax_focus_web_area.swift`:

- activates the target browser app,
- raises the selected Safari window,
- traverses the AX tree with `GENESIS_V100_AX_MAX_DEPTH` and
  `GENESIS_V100_AX_MAX_NODES`,
- stops at the first `AXWebArea`,
- attempts `AXFocusedUIElement` / `AXFocused` assignment,
- emits role counts and focus statuses.

The traversal is deliberately bounded. The page DOM under `AXWebArea` can be
large; this probe only needs to find the top web-content container.

## Key Probe

`scripts/run_v100_open_web_ax_webarea_key_probe.sh` then runs:

1. `pre_focus` Shadow Map,
2. AX WebArea focus probe,
3. `pre_key` Shadow Map,
4. one restricted key through `genesis-os-driver`,
5. `post_key` Shadow Map,
6. URL and topology assertions.

Dry-run mode must report `key_posted=false`.

Armed mode requires:

```bash
GENESIS_V100_ARMED_CONFIRM=GENESIS_V100_ARMED_OPEN_WEB_AX_WEBAREA_KEY \
GENESIS_V100_AUTO_KEY_CONFIRM=GENESIS_V100_AUTO_KEY_WEBAREA_PROBE \
./scripts/run_v100_open_web_ax_webarea_key_probe.sh
```

## Acceptance

Keyboard scrolling is only hunter-safe if a single armed run produces:

- `web_area_found=true`
- `web_area_focus_success=true`
- `url_changed_after_key=false`
- `window_id_stable=true`
- `key_posted=true`
- `key_absorbed_by_content=true`

If the key changes the URL, the probe emits `v100_ax_webarea_key_abort` and
stops immediately.

## Validation

```bash
./scripts/validate_v100_open_web_ax_webarea_key_probe.sh
```
