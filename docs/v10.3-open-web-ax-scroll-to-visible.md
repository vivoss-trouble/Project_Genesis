# Genesis v10.3 Open-Web AX ScrollToVisible Probe

v10.2 found no global page-scroll valve in Safari's `AXWebArea`, but it did
confirm a target-centric control surface: page descendants expose
`AXScrollToVisible`. v10.3 tests that route without using `genesis-os-driver`.

## Boundary

Dry-run mode:

- opens a fresh authorized Rust Book Safari document,
- accepts only Shadow Maps from a window whose title matches the authorized
  target title needle,
- captures a pre-AX Shadow Map,
- locates the top `AXWebArea`,
- optionally probes `AXTextMarkerForPosition -> AXUIElementForTextMarker` from a
  visible Shadow Map point,
- searches for a descendant matching `GENESIS_V103_AX_TARGET_TITLE`,
- verifies that descendant exposes `AXScrollToVisible`,
- captures a post-AX Shadow Map,
- asserts no URL or topology mutation.

Armed mode is required before calling `AXScrollToVisible`.

## Armed Probe

```bash
GENESIS_V103_ARMED_CONFIRM=GENESIS_V103_ARMED_OPEN_WEB_AX_SCROLL_TO_VISIBLE \
GENESIS_V103_AUTO_AX_CONFIRM=GENESIS_V103_AUTO_AX_SCROLL_TO_VISIBLE \
./scripts/run_v103_open_web_ax_scroll_to_visible.sh
```

The armed probe is accepted only if:

- `target_found=true`,
- `scroll_to_visible_available=true`,
- `ax_mutation_attempted=true`,
- `url_changed_after_ax=false`,
- `window_id_stable=true`.

`ax_scroll_to_visible_moved_content=true` is the success signal for content
remap.

The runner binds URL checks to the target Safari document instead of trusting
Safari's generic `front document`, because multi-window Safari state can leave a
non-target document in front while the authorized Rust Book document still
exists in the background.

## Validation

```bash
./scripts/validate_v103_open_web_ax_scroll_to_visible.sh
```

Validation remains dry-run and requires:

- `web_area_found=true`,
- `target_found=true`,
- `scroll_to_visible_available=true`,
- `ax_mutation_attempted=false`,
- `posted=false`,
- `visual_change_detected=false`,
- `url_changed_after_ax=false`.
