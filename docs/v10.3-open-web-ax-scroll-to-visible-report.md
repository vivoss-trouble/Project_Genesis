# Genesis v10.3 Open-Web AX ScrollToVisible Report

## Result

v10.3 proves the target-driven WebKit control-plane route:

```text
Shadow Map point -> AXTextMarkerForPosition -> AXUIElementForTextMarker
AX descendant target -> AXScrollToVisible -> Shadow Map remap
```

The probe found the Safari `AXWebArea`, resolved a visible Shadow Map point
through WebKit's text-marker bridge, found the offscreen Rust Book link titled
`Final Project: Building a Multithreaded Web Server`, and verified that the
target exposes `AXScrollToVisible`.

## Dry-run Evidence

Dry-run remained read-only:

- `web_area_found=true`
- `marker_bridge.text_marker_status=success`
- `marker_bridge.ui_element_status=success`
- `target_found=true`
- `scroll_to_visible_available=true`
- `ax_mutation_attempted=false`
- `posted=false`
- `physical_input_posted=false`
- `url_changed_after_ax=false`
- `visual_change_detected=false`

The selected target was an `AXLink` with `AXScrollToVisible` available. Its
initial frame was far below the visible viewport, confirming the target was a
valid offscreen navigation candidate.

## Armed AX Evidence

The armed probe executed exactly one bounded AX action and did not post any
CoreGraphics physical input:

- `ax_mutation_attempted=true`
- `scroll_to_visible_status=success`
- `target_visible_after_action=true`
- `ax_scroll_to_visible_moved_content=true`
- `url_changed_after_ax=false`
- `window_id_stable=true`
- `posted=false`
- `physical_input_posted=false`
- `os_driver_active=false`

The target's AX frame moved from offscreen (`center_y` around `4064.5`) to
visible (`center_y=579.5`). The post-action Shadow Map detected a topology
change while preserving the same URL and Safari window identity.

The runner also now guards against Safari multi-window drift by accepting only
Shadow Maps captured from a window whose title matches the authorized Rust Book
window. URL checks are bound to the target document instead of the generic
Safari `front document`.

## Boundary

v10.3 does not click, keypress, or scroll through `genesis-os-driver`. The only
armed mutation is a single Accessibility action on a verified descendant that
already exposes `AXScrollToVisible`. If URL mutation is detected, the runner
fails fast.

## Conclusion

WebKit denies global scroll-valve control, but it accepts target-centric
control-plane navigation. The viable v10 route is no longer blind wheel or
keyboard delivery; it is:

```text
Find AX descendant -> AXScrollToVisible -> Remap -> Occlusion/assertion court
```
