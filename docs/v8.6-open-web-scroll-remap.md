# Genesis v8.6 Open-Web Scroll Projection & Remap

v8.6 brings scroll-wheel projection back into the open-web shadow-mapping
pipeline without allowing physical mutation.

The goal is not to scroll a public page yet. The goal is to prove that the v8.5
containment topology can survive a deterministic scroll-state remap:

1. Capture the unscrolled v8 fixture and identify an active `scroll-region`.
2. Send an unarmed `scroll_wheel` request to `genesis-os-driver`.
3. Load the deterministic post-scroll visual state.
4. Re-map the page and assert three physical facts:
   - contained child targets move upward,
  - the scroll-region shell stays fixed within compositor tolerance,
   - targets outside the scroll-region stay fixed.

The fixture exposes the post-scroll state through `?state=scrolled`, which
translates the scroll-region content by `-40px`. This keeps the validation
deterministic while still exercising the same browser window capture and
CoreGraphics projection path used by open-web recon.

## Redline

```bash
./scripts/validate_v86_open_web_scroll_remap.sh
```

Expected facts:

- `os_driver_scroll.receipt.posted=false`
- `v86_open_web_scroll_remap_summary.child_window_y_delta < -20`
- `outside_window_y_delta` remains within a tight browser reload tolerance
- `scroll_region_window_y_delta` remains near zero, with a small compositor
  tolerance because shifted child pixels can move the filled-region centroid

v8.6 remains a projection-only validation. No click, no real browser mutation,
and no armed OS driver path are used.
