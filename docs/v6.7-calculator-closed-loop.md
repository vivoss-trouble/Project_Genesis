# Genesis v6.7 Calculator Closed Loop

v6.7 stitches the v6 stack into one dry-run-first control loop:

```text
Map -> Fire -> Settle -> Assert
```

## Boundaries

- `Map` is still Calculator window topology extraction.
- `Fire` is delegated to the v6.3 sequence gate.
- `Settle` is delegated to the v6.5 settle mode.
- `Assert` is delegated to the v6.6 display hash layer.

The closed-loop script does not create a new driver path. It coordinates the
existing mechanisms and preserves their safety keys.

## Dry-Run

```bash
./scripts/validate_v67_calculator_closed_loop.sh
```

If no expected baseline is supplied, dry-run captures the current display as a
self-baseline, runs the sequence with `posted=false`, and asserts the display
still matches. This validates the pipeline without physical clicks.

## Armed Mode

Armed mode requires an expected display baseline captured before the run:

```bash
GENESIS_V67_EXPECTED_BASELINE_JSON=/tmp/genesis_v66_baselines/display_3.json \
GENESIS_V67_ARMED_CONFIRM=GENESIS_V67_ARMED_CALCULATOR_CLOSED_LOOP \
GENESIS_V67_AUTO_FIRE_CONFIRM=GENESIS_V67_AUTO_FIRE_CLOSED_LOOP \
GENESIS_V67_TARGET_SEQUENCE=calculator-cell-r3-c0,calculator-cell-r3-c3,calculator-cell-r3-c1,calculator-cell-r4-c3 \
  ./scripts/run_v67_calculator_closed_loop.sh
```

The script refuses armed mode without `GENESIS_V67_EXPECTED_BASELINE_JSON`.
This prevents self-baselining after the shot.

## Final Evidence

The terminal emits:

```json
{
  "event": "v67_closed_loop_summary",
  "sequence_complete": true,
  "posted": false,
  "assert_match": true
}
```

For a real closed-loop physical success, the same event must report
`posted=true` and `assert_match=true`.
