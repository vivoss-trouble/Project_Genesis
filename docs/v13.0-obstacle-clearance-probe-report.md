## Observed AX Shape

Safari exposes the fixture modal as an `AXGroup` with subrole
`AXApplicationDialog`. The blocked `Next chapter` target can still have its
center point inside the modal frame, so the clearance probe must scan the
occluder subtree rather than every control whose center is inside the occluder
bbox.

Safari also exposes button text through both `AXTitle` and `AXDescription`.
Whitelist adjudication therefore matches individual title, description, and
value fields exactly instead of matching the concatenated label.

## Guardrails Verified

- Matching browser window title is mandatory; the probe no longer falls back to
  an arbitrary Safari window.
- `AXWindow` is an allowed traversal root.
- Candidate search is bounded to the occluder subtree and bbox.
- Occluder identity requires a real dialog role/subrole or a specific modal-like
  label; generic page content containing the word `obstacle` is not treated as
  armor.
- Trap controls containing `accept`, `subscribe`, or `continue` are rejected.
- Dry-run emits no OS driver action, no AX mutation, and no physical input.
