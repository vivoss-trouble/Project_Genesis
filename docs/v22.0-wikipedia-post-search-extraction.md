# Genesis v22.0 Wikipedia Post-Search Extraction

v22.0 extends the Wikipedia kinetic search path with a read-only post-mutation extraction phase. The execution path still uses the v21.2 search primitive, but after the URL transition it performs a fresh AX scan of the result page and seals the extracted page facts into the evidence pack.

## Scope

- Search query: `OpenAI`
- Armed commit primitive: `os_driver_enter_after_field_focus`
- Result page target: Wikipedia article page under `wikipedia.org`
- Extraction mode: read-only; no additional OS driver event is posted after search commit

## Extraction Contract

The result extractor records:

- current result URL from the runner
- main result title from the AX tree or Safari window title fallback
- lead/body candidate selected by volumetric text-mass scanning
- optional table-of-contents candidates

The extractor does not trust stale plan coordinates. It only runs after the URL transition and only asserts success when:

- the result URL remains inside the domain lock
- the title resolves to the query target
- the lead/body text has enough physical text mass to be useful

## Replay Contract

`run_profile=v22.0-wikipedia-result-extraction` adds a replay requirement for:

- `json/03_step-2-result-extraction_post_assert.json`
- `summary.result_extraction_asserted=true`
- non-empty `summary.result_title`
- `summary.result_lead_text_length >= 40`

The kinetic source remains `raw/v21b_exec_results.jsonl` because the physical mutation primitive is inherited from the v21.2 Wikipedia search chain.
