# Genesis v21.0a Deep-Water Readiness Recon Report

v21.0a adds the first sovereign deep-water readiness probe without crossing the physical input boundary.

## What Changed

- Added `scripts/run_v210a_deep_water_readiness_recon.sh`.
- Added `scripts/validate_v210a_deep_water_readiness_recon.sh`.
- Extended `scripts/replay_v202_evidence_pack.sh` with a manifest-gated read-only recon profile.
- Documented the v21.0a evidence and replay contract.

## Design Result

The key change is profile isolation.

The legacy v20.1/v20.2 dry-run contract remains strict. v21.0a can only use the relaxed read-only stop reasons when the evidence manifest declares:

```json
{
  "run_profile": "v21.0a-read-only-recon",
  "read_only_recon": true,
  "armed": false
}
```

This lets a real public page produce either a ready plan or a bounded `plan_not_ready_read_only_boundary` without turning ambiguity into a failure or a physical action.

## Validation Matrix

Expected assertions:

- `posted=false`
- `physical_input_posted=false`
- `os_driver_active=false`
- `domain_locked=true`
- `cryptographic_seal_ok=true`
- `replay status=ok`
- `time_tear_fatal_enforced=true`
- `step_count=0`

The target may return `plan_ready=false`. For v21.0a, that is a valid recon conclusion, not a tactical failure.
