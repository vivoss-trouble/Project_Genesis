# Genesis v9.9 Open-Web AX Key Route Probe

v9.8 proved that macOS Accessibility can raise and focus the target Safari
window without physical input or page mutation. v9.9 tests the next boundary:
after that clean focus assignment, will one restricted key route into web
content, or will it still escape into Safari chrome?

## Pipeline

`scripts/run_v99_open_web_ax_key_route_probe.sh` performs:

1. open the authorized URL,
2. capture `pre_focus`,
3. run the v9.8 AX focus helper,
4. capture `pre_key`,
5. send one restricted key through `genesis-os-driver`,
6. capture `post_key`,
7. assert URL and topology state.

The default key is `page_down`:

```bash
GENESIS_V99_KEY=page_down ./scripts/run_v99_open_web_ax_key_route_probe.sh
```

## Armed Gate

Dry-run mode uses an unarmed driver and must report `key_posted=false`.

Armed mode requires both keys:

```bash
GENESIS_V99_ARMED_CONFIRM=GENESIS_V99_ARMED_OPEN_WEB_AX_KEY_ROUTE \
GENESIS_V99_AUTO_KEY_CONFIRM=GENESIS_V99_AUTO_KEY_ROUTE_PROBE \
./scripts/run_v99_open_web_ax_key_route_probe.sh
```

Only one key is sent. If the key changes the URL, the script emits
`v99_ax_key_route_abort` and exits immediately.

## Acceptance

A key is not considered hunter-safe merely because it posts successfully. It
must satisfy all of:

- `url_changed_after_focus=false`
- `url_changed_after_key=false`
- `window_id_stable=true`
- `key_posted=true` in armed mode
- `key_absorbed_by_content=true`

Until those are observed together, keyboard scrolling remains outside the
autonomous hunter controller.

## Validation

```bash
./scripts/validate_v99_open_web_ax_key_route_probe.sh
```
