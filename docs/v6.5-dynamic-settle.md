# Genesis v6.5 Dynamic Settle

v6.5 replaces blind sequence waiting with an auditable settle layer while
preserving the v6.3 fire-control path.

## Invariant

Dynamic settle can decide when the next map is allowed to start. It cannot
select targets, mutate coordinates, or post physical actions.

## Modes

```bash
GENESIS_V65_SETTLE_MODE=fixed
GENESIS_V65_SETTLE_MODE=dynamic
GENESIS_V65_SETTLE_MODE=hybrid
```

- `fixed` preserves the original `GENESIS_V63_SETTLE_MS` sleep.
- `dynamic` runs the v6.4 frame-stability probe and aborts the sequence if the
  probe cannot prove the Calculator window is stable.
- `hybrid` runs the same probe, then falls back to the fixed wait if the probe
  fails. This is the default.

## Audit Event

Each sequence step emits:

```json
{
  "event": "v65_sequence_settle",
  "step_index": 0,
  "target_id": "calculator-cell-r3-c0",
  "mode": "hybrid",
  "stable": true,
  "elapsed_ms": 512.0,
  "fallback_used": false,
  "posted": false
}
```

The event turns time into first-class evidence. If `fallback_used` is `true`,
the probe failed or timed out and the fixed mechanical wait took over.

## Validation

```bash
./scripts/validate_v65_dynamic_settle.sh
```

The validation runs dry-run only and asserts one `v65_sequence_settle` event per
sequence item, no OS-driver receipt posts, and a summary with the requested
settle mode. It also forces the frame-stability probe to fail once and asserts
that `hybrid` emits `fallback_used=true` while still keeping every receipt
`posted=false`.
