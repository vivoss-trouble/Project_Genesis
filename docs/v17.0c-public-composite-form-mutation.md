# Genesis v17.0c Public Composite Form Mutation

## Purpose

v17.0c composes the public business mutation primitives into one serial
orchestrated flow. It deliberately keeps each primitive isolated instead of
building a monolithic AX probe:

```text
TextField mutation
  -> fresh process boundary
Checkbox mutation
  -> fresh process boundary
Combobox mutation
  -> composite assertion
```

The goal is to prove the interaction vocabulary can switch weapons across
continuous text input, binary state collapse, and Z-axis combobox selection
without leaking URL state or reusing stale GUI context.

## Architecture

The controller is a shell-level orchestrator. It launches the existing sealed
public primitives serially:

- v16.0 `run_v160_public_controlled_business_mutation.sh`
- v17.0a `run_v170a_public_binary_state_collapse.sh`
- v17.0b `run_v170b_public_combobox_state_collapse.sh`

Each subprocess owns its own target page, remap, mutation, assertion, and cleanup
boundary. The v17.0c controller only accepts each subprocess summary and emits a
single composite court receipt.

## Red Lines

- GUI/OS armed validation must run serially.
- The controller must not cache any AX node between primitive steps.
- A subprocess API success is not evidence; only each subprocess summary is
admissible.
- `url_unchanged=true` is mandatory for every armed primitive.
- `state_pollution_detected=false` is mandatory for the composite receipt.
- Dry-run must stop before physical business-state completion.
