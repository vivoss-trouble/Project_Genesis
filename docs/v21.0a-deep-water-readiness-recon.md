# Genesis v21.0a Deep-Water Readiness Recon

v21.0a is a zero-kinetic public recon pass before any sovereign deep-water armed run.

It intentionally exercises only:

- v19.0 public read-only planning
- v20.3 temporal-hardened evidence packaging
- v20.2 offline replay verification

No OS driver is started and no physical input is posted.

## Target

The default target is `https://www.wikipedia.org/`.

This is a low-side-effect public knowledge entry point. It is intentionally not treated as a guaranteed executable business plan. `plan_ready=false` is a valid outcome as long as the planner returns a bounded stop reason and the evidence chain remains sealed.

## Evidence Profile

`run_v210a_deep_water_readiness_recon.sh` writes a v20.3 evidence pack with:

- `run_profile: v21.0a-read-only-recon`
- `read_only_recon: true`
- `armed: false`
- `posted: false`
- `physical_input_posted: false`
- `os_driver_active: false`

The ledger records:

- `json/00_intent_plan.json`
- `json/01_public_recon_planner_summary.json`
- window-scoped snapshot JSON and best-effort PNG status
- `json/99_terminal_scan_report.json`
- `json/99_v20_summary.json`
- a SHA-256 manifest with v20.3 temporal hardening

## Replay Contract

The v20.2 verifier accepts this profile only when the manifest explicitly declares `run_profile: v21.0a-read-only-recon`.

Allowed read-only boundaries:

- `plan_ready_read_only_boundary`
- `plan_not_ready_read_only_boundary`

Fatal conditions:

- any posted physical input
- OS driver activation
- domain lock failure
- missing or tampered ledger files
- missing temporal hardening
