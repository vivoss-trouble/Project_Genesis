# Genesis v13.5 Obstacle ISR Controller

v13.5 mounts the independent v13.0 obstacle clearance probe as an outer
interrupt service routine. It does not merge the v12 pagination loop and v13
clearance probe into one binary.

## Clock Law

```text
main loop detects occlusion
  -> emit obstacle_clearance interrupt
  -> freeze current target context
  -> launch v13.0 clearance child process
  -> accept only click_posted=true and target_clear_after=true
  -> force the caller to perform a fresh v12 remap before resuming
```

The controller consumes child JSON receipts instead of importing the clearance
implementation. That keeps the probes independently testable and preserves
post-mortem boundaries.

## Dry-Run Validation

```bash
./scripts/validate_v135_obstacle_isr_controller.sh
```

Expected dry-run facts:

- `interrupt_requested=obstacle_clearance`
- `main_loop_frozen=true`
- frozen context includes `target_point` and `occluder_frame`
- child v13.0 clearance remains dry-run
- `resume_allowed=false`
- `stop_reason=dry_run_isr_projection_stop`
- no physical input is posted

## Armed Fixture Command

```bash
GENESIS_V135_ARMED_CONFIRM=GENESIS_V135_ARMED_ISR_CONTROLLER \
GENESIS_V135_AUTO_FIRE_CONFIRM=GENESIS_V135_AUTO_FIRE_ISR_CONTROLLER \
./scripts/run_v135_obstacle_isr_controller.sh
```

Armed mode delegates exactly one physical clearance click to v13.0. A successful
ISR requires the v13 child receipt to prove:

```json
{
  "click_posted": true,
  "target_clear_after": true,
  "stop_reason": "complete"
}
```

When that shape is observed, v13.5 emits `resume_allowed=true` and
`requires_fresh_v12_remap=true`. The caller must still rerun the v12 perception
pipeline; old coordinates are never reused.
