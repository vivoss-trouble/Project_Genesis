# Genesis v15.0 Long-Clock ISR Pagination Loop

## Goal

v15.0 fuses the v12 pagination loop with the v13/v14 ISR clearance path in a deterministic local battlefield. The purpose is to prove that a long-clock controller can keep the main pagination clock clean while one step is interrupted by a modal obstacle.

## Fixture

The local fixture lives in `fixtures/v15/`:

- `page0.html`: clear page with one `Next chapter` target.
- `page1.html`: `Next chapter` is covered by a modal dialog with one legal `Close` button and three blacklisted traps.
- `page2.html`: clear page with one `Next chapter` target.
- `page3.html`: terminal page with no `Next chapter`.

The expected route is:

```text
page0 -> page1 -> page2 -> page3 -> target_not_found_terminal_ok
```

## Control Rules

- `MAX_STEPS=3`.
- `MAX_ISR_PER_STEP=1`.
- `MAX_SAME_URL_COUNT=1`.
- `TARGET_NOT_FOUND_TERMINAL_OK=1`.
- ISR execution freezes the main pagination counters.
- After ISR clearance, the controller must perform a fresh v12-style remap before resuming the main click.
- If the same step is still occluded after one ISR, the controller must stop with `recursive_occlusion_fatal`.

## Expected Receipt

```json
{
  "total_pagination_steps": 3,
  "isr_triggered_count": 1,
  "isr_step_interventions": [1],
  "clearance_click_posted": true,

  "final_stop_reason": "target_not_found_terminal_ok",
  "state_pollution_detected": false,
  "sequence_complete": true
}
```
