# Genesis v15.5 Business State Flow

## Goal

v15.5 adds a controlled state mutation after ISR clearance. It keeps the OS driver stateless, first attempts a scoped AX form write, and then verifies the live business state through a fresh AX assertion.

## Fixture

`fixtures/v15_5/business_form.html` starts with a modal covering a business form. The form contains:

- `Operator Code` text field.
- `Mission Mode` select control.
- `Commit profile` button.
- `Profile Status` status node.

The modal contains one whitelisted `Close` button and three blacklisted traps.

## Flow

```text
S1 modal state
  -> v13-style clearance probe
  -> OS Driver click on Close
  -> fresh remap
  -> AX write Operator Code
  -> if WebKit does not reflect AXValue into the live field, focus the field and type the value through System Events
  -> OS Driver click Commit profile
  -> AX assertion profile_saved:<code>:standby
```

## Safety Lines

- Dry-run stops before physical input.
- Clearance remains whitelist-only.
- Form state mutation requires `GENESIS_V155_MUTATE_CONFIRM=GENESIS_V155_MUTATE_FORM_STATE`.
- AX write reflection is audited separately from live field readiness. Safari may return AX success while leaving the DOM input unchanged.
- The text fallback is only entered after the AX attempt and is verified by a fresh field read before commit.
- The final commit must not change URL.
- The business assertion must be observed after the commit click.

## Commands

Dry-run:

```bash
./scripts/run_v155_business_state_flow.sh
```

Validation:

```bash
./scripts/validate_v155_business_state_flow.sh
```
