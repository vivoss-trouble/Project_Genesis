# Genesis v9.8 Open-Web Focus Route Probe

v9.7 proved that keyboard events can penetrate macOS, but it also exposed a
responder-chain hazard: `page_down` and `arrow_down` changed the front Safari
URL when the key event was not confidently routed to the web content area.

v9.8 does not try another key and does not inject a neutral click. It first
tests the cleaner control plane: macOS Accessibility focus assignment.

## Probe Contract

`scripts/run_v98_open_web_focus_route_probe.sh`:

1. opens the authorized Safari URL,
2. captures a pre-focus Shadow Map,
3. runs `scripts/ax_focus_browser_window.swift`,
4. captures a post-focus Shadow Map,
5. asserts that no URL change or physical input occurred.

The probe emits:

```json
{"event":"v98_ax_focus_probe","posted":false,"physical_input_posted":false}
{"event":"v98_focus_route_probe_result","url_changed":false,"os_driver_active":false}
```

## Safety Boundary

The probe never starts `genesis-os-driver`, never sends keyboard input, never
scrolls, and never clicks. A successful run only proves that the target Safari
window can be activated and raised without mutating page state.

Keyboard scrolling remains disallowed for the hunter controller until a later
probe proves all of the following in the same run:

- the target URL stays unchanged,
- the target window identity stays stable,
- a bounded key produces nonzero content displacement,
- post-map classification remains coherent.

## Validation

```bash
./scripts/validate_v98_open_web_focus_route_probe.sh
```
