# Genesis v5.5 Vision Marker Single-Shot Gate

v5.5 wires the deterministic v5.4 marker detector into the real macOS motor
path while keeping the v5.3 armed manual gate.

## Boundary

- This is a single-shot gate, not continuous fire.
- Dry-run mode never posts mouse events.
- Armed mode requires `GENESIS_V55_ARMED_CONFIRM=GENESIS_V55_ARMED_VISION_MARKER`.
- Before any vision capture, the operator must uncover the Native Dummy marker
  and type `VISIBLE`, unless `GENESIS_V55_VISIBLE_CONFIRM=VISIBLE` is explicitly
  set for noninteractive testing.
- Armed mode also requires typing `FIRE` unless `GENESIS_V55_FIRE_CONFIRM=FIRE` is explicitly set.
- Coordinates come from `marker_detection.coregraphics_logical_center`, not from hardcoded Native Dummy geometry.
- If marker detection is absent, the script refuses to click and prints `marker_sample` evidence from the expected point.

## Dry Run

```bash
./scripts/run_v55_vision_marker_single_shot.sh
```

When prompted, move the terminal away from the Native Dummy and type:

```text
VISIBLE
```

Expected outcomes:

- If Screen Recording is granted and the Native Dummy marker is visible,
  `marker_detection` contains a CoreGraphics logical center and the OS driver
  receipt reports `posted=false`.
- If the marker is not visible or the framebuffer does not contain the marker at
  the expected point, the script stops before action and prints raw sampled pixel
  evidence.

## Armed Single Shot

```bash
GENESIS_V55_ARMED_CONFIRM=GENESIS_V55_ARMED_VISION_MARKER \
  ./scripts/run_v55_vision_marker_single_shot.sh
```

After the Native Dummy appears, type:

```text
VISIBLE
```

If `marker_detection` succeeds and the armed gate is reached, type:

```text
FIRE
```

The script then sends exactly one `move_mouse` and one `click_point` to
`genesis-os-driver` using the live marker-derived CoreGraphics coordinate.

## Physical Meaning

A successful `native_dummy_hit` here proves:

```text
Screen pixels -> marker detector -> CoreGraphics logical coordinate -> os-driver -> AppKit hit-test
```

No YOLO, OCR, model perception, planner logic, or Core control-flow change is
involved.
