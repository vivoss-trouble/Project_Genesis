# Genesis v8.2 Open-Web Drift Telemetry

v8.2 adds a sliding-window telemetry layer on top of v8.1 shadow mapping.

The goal is to measure map-to-map stability before any pre-fire correction or
public-web live-fire logic exists.

## Invariant

```text
sample N shadow maps
compare stable target IDs
compute centroid drift and taxonomy flicker
posted=false
os_driver_active=false
```

The sampler never opens an OS-driver socket and never emits input events.

## Metrics

- `max_centroid_drift_px`
- `max_window_origin_drift_px`
- `mean_centroid_drift_px`
- `stddev_centroid_drift_px`
- `kind_switch_count`
- `missing_frames`
- `mean_capture_latency_ms`

## Deterministic Validation

The redline uses the local v8.1 static document sample:

```bash
./scripts/validate_v82_open_web_drift_telemetry.sh
```

Expected baseline:

- no taxonomy flicker
- no missing targets
- maximum centroid drift under `0.5px`
- `posted=false`
- `os_driver_active=false`

## Public Page Probe

Public pages are telemetry probes, not redlines:

```bash
GENESIS_V82_URL="https://doc.rust-lang.org/book/" \
GENESIS_V81_WINDOW_TITLE="Rust" \
GENESIS_V82_SAMPLE_COUNT=20 \
  ./scripts/run_v82_open_web_drift_telemetry.sh
```

Centroid drift is measured in window-local coordinates. Window-origin drift is
reported separately so OS/window-manager movement does not masquerade as web
layout shift.

Use these samples to decide whether v8.3 needs pre-fire correction,
frame-stability gating, or a trigger-style snapshotter.
